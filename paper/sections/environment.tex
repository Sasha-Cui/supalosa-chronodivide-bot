\section{Environment and Evidence Contract}
\label{sec:environment}

\subsection{Chrono Divide and literal victory}

Chrono Divide is an existing browser reconstruction of \emph{Red Alert 2}; the
public game API can initialize headless offline matches and provide structured
game state, production, and action interfaces
\cite{chronodivide2026,chronodivideGameApi2026}. We pin game API 0.75.0,
Node.js 20.13.1, the map bytes, and the runtime asset manifest. Original game
archives are acquired separately and are not redistributed.

The candidate and opponent begin with 10,000 credits, superweapons disabled,
MCV repacking enabled, and short-game defeat disabled. A game is a win only
when every opponent building has been physically removed. We suppress both
bots' resignation calls symmetrically and record every attempt. Engine
termination that does not establish one side's literal building elimination is
a draw; unresolved games end as draws at 90,000 updates. The primary endpoint
is W/D/L, with paired score $1/0.5/0$ used only for policy contrasts.

This endpoint matters. An army can survive after its final building is
destroyed, in which case the other side has already won. Conversely, a large
material advantage is not converted into a win if the bot cannot locate and
destroy the remaining structures. Section~\ref{sec:frames} shows both a literal
win with surviving enemy personnel and a genuine 90,000-update failure.

\subsection{Candidate and isolated opponent}

Supalosa is a public scripted Chrono Divide bot
\cite{supalosa2026bot}. StrongBot is an author-developed derivative that keeps
the upstream economic and mission framework while adding scoped strategic and
terminal-objective layers. All claims compare against a separate clean checkout
of Supalosa commit \texttt{165b77a}. Candidate imports cannot modify that tree.
The harness verifies its Git identity, compiled runtime hash, package version,
and clean status before every accepted campaign.

The independently sourced transfer opponent is the frozen RA2Web Advanced
bundle~\cite{ra2web2026bot}. Its byte hash, client release, and freeze
manifest are recorded. We make no claim that this one version represents all
RA2Web bots.

\subsection{Deterministic paired simulation}

The pinned API exposes no public offline seed. Runtime inspection showed that
the engine derives its Mersenne Twister from game identity and epoch seconds,
whereas bot callbacks consume process-global \texttt{Math.random}. The harness
therefore maps a requested 32-bit seed to the creation-time clock only while
the game initializes and wraps candidate and opponent callbacks with distinct
identity-keyed Mulberry32 streams. Extra random draws by one participant cannot
advance the other stream, and swapping participant array order does not swap
their streams. All globals and callbacks are restored in \texttt{finally}
blocks.

A fresh-process gate produced ten byte-identical normalized traces at one seed
and a distinct trace at another. Every comparison reuses the same engine and
participant streams for paired policies. The requested seed, participant
identities, map, physical start, slot, source, runtime, and opponent hashes are
stored with each cell.
